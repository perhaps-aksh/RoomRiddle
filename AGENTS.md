# RoomRiddle Development Rules

These rules apply to every agent (Hermes, Claude, Codex…) and human working in this repo. Read the whole file before changing code.

## Project
RoomRiddle is a multiplayer mystery game platform for Amazon Fire TV / Vega OS, built for the *Build, Ship, Shape: Amazon Developer Hackathon* (submission deadline **2026-10-23, 12 PM PT**).

- The **TV** is the primary game stage.
- **Phones** are companion investigation devices.
- The **server** is authoritative.

Tagline: *Gather. Investigate. Unravel the Mystery.*

## Current development strategy
Build the deterministic game first. **AI is deferred.**

Do NOT introduce any of these unless explicitly requested later:
- Gemini, OpenAI, Claude or any other LLM API
- RAG or vector databases
- AI-generated clues, hints, story, puzzle answers or answer validation
- LLM agents inside the app

Also not without a concrete requirement: Redis, PostgreSQL, Firebase, AWS services, complex auth, microservices. In-memory server state is fine.

## Architecture
| Part | Stack | Location |
|---|---|---|
| TV | React Native for Vega + TypeScript | `apps/tv` (generated by Vega tooling, see its README) |
| Player | Mobile web → PWA → Android | `apps/player` |
| Server | Node.js + TypeScript + WebSockets | `apps/server` |
| Shared types | TypeScript | `packages/shared-types` |
| Game engine | Pure TypeScript, deterministic | `packages/game-engine` |
| Mystery content | TypeScript data modules | `packages/mystery-data` |
| Design tokens | Plain values, no framework imports | `packages/ui` |

Flow: `Mystery Data → Game Engine → Game State → UI`. The TV and phones talk to the server over WebSockets. They never talk to each other directly.

## Game logic
Game rules must be deterministic. The server and game engine control answers, puzzle validation, hints, scoring, timers, unlocks, choices and endings.

- Clients send **intents** ("my answer is 1147") and never claim results ("I solved it").
- Clients never decide their own correctness, and answer keys never reach a client before they're needed.
- The engine is mystery-agnostic. Never hard-code a mystery in UI or engine code (`if (puzzleId === 'train_puzzle_1')` is banned). Mystery-specific behaviour belongs in `packages/mystery-data`.
- The engine does no I/O, no `Math.random()` without an injected seed, and no `Date.now()`. Time is passed in.
- Hints are pre-authored and progressive: 1 directional, 2 interpretation, 3 near-solution.

## TV rules
- Everything works with a remote: Up, Down, Left, Right, Select/OK, Back. Never rely on touch.
- Every focusable element has an obvious focus state, readable from the couch.
- Back never destroys a room, active gameplay or player progress without explicit confirmation.
- Large type (TV body text ≥ 28), high contrast, cinematic but calm. Use the tokens in `packages/ui`.

## Development rules
1. Inspect existing code before modifying it.
2. Never delete existing work without explicit approval.
3. Don't rewrite the project unnecessarily. Prefer incremental changes.
4. Work milestone by milestone, and stop at the end of each milestone to report.
5. Keep changes small and testable.
6. Prefer data-driven systems.
7. Avoid unnecessary dependencies. Justify every new one.
8. Keep the TV UI usable with a remote/D-pad.
9. Keep the player UI optimized for phones.
10. Document significant architectural decisions in `docs/architecture.md`.
11. No fake implementations presented as complete. Placeholders must say they're placeholders.

For every task: inspect → read this file → identify files → briefly explain the plan → make the smallest correct change → `npm run check` → review the diff → commit.

## Commands (repo root, Windows or Linux)
```bash
npm install          # installs all workspaces except apps/tv
npm run typecheck    # tsc over packages/* + apps/server + apps/player
npm test             # node:test via tsx in every workspace that has tests
npm run check        # typecheck + test; must pass before every commit
npm run dev:server   # server in watch mode on http://127.0.0.1:4000 (GET /health)
```
The TV app (`apps/tv`) is built with the Vega CLI from a Linux/macOS shell. See `docs/development.md`.

## Git
- Small commits per milestone, conventional messages: `feat:`, `fix:`, `chore:`, `docs:`, `test:`, `refactor:`.
- Run `npm run check` before committing. Never commit secrets (`.env`, keys, tokens). Future API keys live server-side only.
- Never force-push, reset or rewrite shared history without explicit approval.

## Friction log and product feedback
Record every real problem with Vega, the VVD, React Native, remote navigation, the build system, networking or tooling in `docs/friction-log.md`, as it happens. Never invent entries. Product feedback on Amazon tools also goes in docs and must only reflect actual experience.

## Current mystery
